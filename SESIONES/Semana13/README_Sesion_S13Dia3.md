# Día 3 — Datos distribuidos y consistencia eventual

## Objetivos
Diseñar consultas y procesos sin joins entre servicios.

## Contenido
- database per service;
- proyecciones locales;
- eventos de integración;
- sagas/compensaciones como profundización;
- idempotency key para comandos HTTP.

## Laboratorio
Crear reporte local de notificaciones desde eventos. Simular retraso y explicar al usuario la consistencia eventual.

## Discusión
Comparar composición síncrona, API composition, CQRS de lectura y conservar la funcionalidad en el monolito.

## Criterios
Límites 30%, autonomía de datos 30%, consistencia 25%, defensa técnica 15%.
