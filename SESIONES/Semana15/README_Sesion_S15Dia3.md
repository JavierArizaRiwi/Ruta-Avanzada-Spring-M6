# Día 3 — Operación y fallos distribuidos

## Objetivos
Diagnosticar un sistema de varias instancias y crear runbooks.

## Laboratorio de caos controlado
1. Detener consumidor.
2. Introducir latencia HTTP.
3. Llenar pool de conexiones.
4. Enviar poison message.
5. Recuperar y comprobar backlog.

## Señales
Métricas por servicio/instancia, consumer lag, DLT, circuit breaker, outbox age, readiness y saturación.

## Entregables
Dashboard distribuido, alerta educativa y runbooks para Kafka DLT, outbox y dependencia caída.

## Criterios
Seguridad 25%, trazabilidad 30%, diagnóstico 30%, operación 15%.
